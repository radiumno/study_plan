# 学习量校准规则

> 目标: 让每个阶段和Day都能从时间、依赖和验收解释，而不是靠“看起来差不多”。

## 一、阶段预算

每次规划阶段必须写:

| 项 | 必填 |
|----|------|
| 阶段终点 | 最终交付什么 |
| 岗位映射 | 对应哪个岗位族和能力 |
| 总时间 | 周数、每周次数、单次时长 |
| 主线分配 | 知识、练习、项目、复习 |
| 缓冲 | 10%-20% |
| 验收 | 测试、项目、限时题、表达 |
| 删除项 | 容量不足先删什么 |

注意:

- 校内课程、考研和项目时间不能重复计算。
- AI辅线不是固定配额，只使用主线达标后的剩余容量。
- 远期阶段只做Block预算，当前阶段才细化到Day。

## 二、Day容量

| Day类型 | 合理时长 | 新概念 | 典型产出 |
|---------|----------|--------|----------|
| 新知识入门 | 2-2.5h | 1-2个 | 小实验/函数 |
| 常规技能 | 2.5-3h | 2-3个 | 可运行模块 |
| 强练习 | 2.5-3h | 0-1个 | 综合题/错题复做 |
| 项目 | 3-4h | 0-1个 | 一个可验证模块 |
| 测试/复盘 | 2-4h | 0个 | 验收和薄弱点 |

## 三、超量信号

出现任一项必须拆分、后移或改选做:

- 新概念超过3个。
- 同时引入新库、新数据源和新项目结构。
- 练习超过10道且还有大综合。
- 一天要交付多个互不相关的产出。
- 前一Day未Review通过。
- 时间预算依赖“用户肯定会很快”。
- AI、考研和主线同时按满额排入。

## 四、Day学习量卡

| 项 | 要求 |
|----|------|
| 唯一主目标 | 一句话可验收 |
| 阶段映射 | 服务哪个阶段终点 |
| 前置 | 哪些内容必须Review通过 |
| 新概念 | 数量和名称 |
| 练习 | 子练习、块练习、综合 |
| 时间 | 复习/教学/练习/综合/复盘 |
| 验收 | 可运行、可测试或可解释 |
| 超量处理 | 删除、后移、选做或拆天 |

没有这张卡，不开始写课。

## 六、阶段2以后

每周默认:

| Day | 用途 |
|-----|------|
| A-B | 新知识 |
| C | 实现/强练习 |
| D | 量化语境模块 |
| E | 限时题或项目整合 |
| R | Review、错题、测试、返工 |

每次只冻结未来1-2周，后续依据学习结果滚动调整。

## 七、复核问题

写完计划或课程后回答:

1. 如果只完成70%，最重要产出还能留下吗？
2. 哪一项最容易被低估时间？
3. 哪个内容只是“有趣”而非阶段必要？
4. 用户上一Day的表现是否支持这个难度？
5. 验收失败后具体返工什么？
