# 学习量校准规则

> 用途: 防止每天课程量凭感觉安排。所有 day / week 的内容都必须从阶段目标、岗位权重、剩余时间和验收产出倒推。

---

## 一,核心原则

1. 先定阶段终点,再拆每天学习量。
2. 每天只服务一个主要产出,最多带一个次要补充。
3. 新知识、练习、项目、复习必须按比例分配,不能把一堆知识点塞进一天。
4. 如果当天内容超过容量上限,必须拆天、移到选做或降级,不能硬写成“预估3h”。
5. 如果当天内容低于容量下限,优先补复习、错题、项目文档或量化小练习,不随便加新技术。

---

## 二,阶段容量预算

每次写或改阶段规划前,先填这张表:

| 项 | 必填内容 |
|----|----------|
| 阶段终点 | 本阶段结束必须能交付什么 |
| 岗位权重 | 这些内容对应哪些真实JD要求,权重多高 |
| 总可用时间 | 几周/几天,每次学习默认几小时 |
| 主线比例 | 量化/C++/项目/AI/考研各占多少 |
| 缓冲比例 | 至少10%-20%留给复习、返工、薄弱点 |
| 验收方式 | 项目、测试、题解、README、回测截图、面试讲述 |

阶段容量不够时,处理顺序:

1. 保留岗位权重最高的主线。
2. 删除炫技内容。
3. 把可选内容放到选做或阶段后。
4. 增加复习日,不要透支后面阶段。

---

## 三,每日容量上限

默认以一次学习 2.5-3 小时为普通 day。难度高或项目型 day 可以到 3-4 小时,但必须说明原因。

| Day 类型 | 合理容量 | 适用内容 |
|----------|----------|----------|
| 新概念入门 | 2-2.5h | 第一次接触的新语法、新库、新工具 |
| 常规技能课 | 2.5-3h | 1个主知识块 + 1个辅助知识块 + 综合练习 |
| 强练习课 | 2.5-3h | 少讲多练,用于巩固易错点 |
| 项目课 | 3-4h | 模块开发、README、测试、可运行产出 |
| 综合测试/复习课 | 2-4h | 闭卷大题、查漏补缺、复盘 |

单日超量信号:

- 新概念超过3个。
- 练习超过10道且还有大综合。
- 同时出现新库、新数据源、新项目结构。
- 用户上一天练习未稳定完成。
- 当天产出无法在一个文件或一个小模块里收束。

出现任一信号,必须拆分或降级。

---

## 四,每日拆分模板

每个 day 的学习量必须能解释清楚:

| 项 | 要求 |
|----|------|
| 阶段目标映射 | 说明当天服务哪个阶段产出 |
| 前置依赖 | 已学过什么,当天新增什么 |
| 内容上限 | 新知识点数量、练习数量、综合题数量 |
| 时间预算 | 复习/学/练/综合/复盘分别多少分钟 |
| 验收产出 | 当天结束必须留下什么可检查成果 |
| 超量处理 | 超过上限时拆到哪一天或降为选做 |

写课程时如果没有这张拆分依据,不能开始写 day 文件。

阶段1终点: 能用 Python/Pandas 处理行情数据,完成 `stock-analysis-tool`,有 README 和最小测试,然后尽快进入 C++/算法。

阶段1禁止加量:

- 不加 Web UI。
- 不加数据库。
- 不加完整AI系统。
- 不加复杂交易系统。
- 不把聚宽/米筐平台操作替代本地实现。

## 六,阶段2以后执行方式

阶段2以后细脉络可以先按 week 写,但每次进入新 week 前必须拆出 4-6 个具体学习 day:

| 周内日型 | 内容 |
|----------|------|
| Day A-B | 新知识/新语法 |
| Day C-D | 专题练习/LeetCode/小模块 |
| Day E | 量化语境小练习或项目整合 |
| Day R | 复盘/错题/补薄弱点 |

不允许直接说“本周学STL/刷题”,必须落到每天的知识点、练习数和验收产出。
