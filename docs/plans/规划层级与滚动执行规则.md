# 规划层级与滚动执行规则

> 用途: 解决主脉络、细脉络、逐日计划和实时进度互相重复、互相漂移的问题。
>
> 更新日期: 2026-07-10

## 一、六层模型

| 层级 | 时间范围 | 回答的问题 | 文件 |
|------|----------|------------|------|
| 证据层 | 季度 | 市场需要什么、资源是否可靠 | 招聘报告、核心资源清单 |
| 主脉络 | 2-3年 | 为什么按这些阶段学习 | `resources/主脉络.md` |
| 阶段细脉络 | 1-6个月 | 本阶段学什么、产出什么 | `docs/plans/阶段X_分脉络大纲.md` |
| 滚动日计划 | 1-2周 | 下一批具体学习日怎么排 | 当前阶段计划内的滚动表 |
| Day课程 | 1次学习 | 今天怎么教、练和验收 | `projects/python/.../dayXX` |
| 实时状态 | 当前 | 现在做到哪、是否Review通过 | `vault/会话交接.md` |

## 二、规划精度

### 当前阶段

- 所有剩余Day必须有目标、依赖、时间、练习范围和验收。
- 允许根据Review结果调整后续Day。

### 下一阶段

- 阶段目标和周级结构必须完整。
- 只提前拆最近1-2周的具体Day。

### 更远阶段

- 只保留能力块、项目和闸门。
- 不提前冻结每一天，避免外部变化和学习反馈让计划失真。

## 三、状态语义

| 状态 | 含义 | 谁可以推进 |
|------|------|------------|
| 计划中 | 只存在阶段计划 | 写课流程 |
| 课程已写 | 课程文件和空练习已完成 | 用户开始学习 |
| 学习中 | 用户正在填写练习 | Code Review |
| 待Review | 练习已提交，尚未验收 | Code Review |
| Review通过 | 命名功能、边界和验收均通过 | 才能进入下一Day |
| 返工 | 未达到验收或前置不稳 | 修复后再次Review |

**硬规则:** 课程文件写完不等于用户学完。只有Review通过才能在阶段计划中标记完成。

## 四、滚动日计划模板

每次只维护未来1-2周:

| Day | 类型 | 唯一主目标 | 前置 | 新概念上限 | 练习范围 | 时间 | 验收 |
|-----|------|------------|------|------------|----------|------|------|
| A | 新知识 |  |  | 2-3 |  | 2.5-3h |  |
| B | 新知识/工具 |  |  | 2-3 |  | 2.5-3h |  |
| C | 强练习 |  |  | 0-1 |  | 2.5-3h |  |
| D | 项目整合 |  |  | 0-1 |  | 3-4h |  |
| R | 复盘/返工 |  |  | 0 |  | 2-3h |  |

## 五、变更传播

| 发生变化 | 必须更新 | 通常不更新 |
|----------|----------|------------|
| 招聘证据改变 | 招聘报告、技能矩阵；必要时主脉络 | Day课程 |
| 阶段目标改变 | 主脉络、对应阶段计划、交接 | 历史课程 |
| Day容量或依赖改变 | 阶段计划、写课流程、交接 | 招聘报告 |
| 用户完成练习 | 交接、阶段计划状态 | 主脉络 |
| 新资源出现 | 候选资源库；确认优于现有后再进核心清单 | 路线比例 |

## 六、冲突解决顺序

1. 已验证的用户实际学习结果
2. `vault/会话交接.md`
3. 当前阶段细脉络
4. `resources/主脉络.md`
5. 历史记忆和旧报告

发现冲突时先修状态和规划，不靠聊天临时解释。

## 七、每周节奏

- 学习日: 3-5次，按用户实际时间调整。
- 新知识日: 最多2-3次。
- 强练习/项目日: 至少1次。
- Review/返工日: 至少1次或保留等量缓冲。
- AI辅线: 只有主线当周通过后才占用剩余时间。
