# 项目整体审查 — 2026-07-10

## 一、结论

旧路线方向大体正确: Python打底，尽早进入C++、算法、Linux和交易系统。

主要问题不在“缺内容”，而在:

1. 招聘证据混合了不同岗位族，并把公开样本写成市场统计。
2. 主脉络、细脉络、AI计划、README和流程存在多套旧口径。
3. 阶段1后半段单日超量，阶段2以后又缺少可执行的滚动日计划。
4. 项目数、LeetCode题数和AI时间比例被当成结果指标。
5. 课程写完、用户学完和Review通过没有分开。
6. 周审与检查脚本能查文档/课程，但不能拦规划漂移。

本轮已完成结构性修正，不改动用户正在填写的Day 11答案。

## 二、外部证据结论

本轮使用公司官方招聘页和官方学生岗位重新核验。

### 岗位必须拆成四类

| 岗位族 | 核心 |
|--------|------|
| 交易系统/低延迟 | C++、Linux、算法、并发、网络、体系结构、性能 |
| 策略系统/研究平台 | C++/Python、Linux、并行、回测、海量数据和系统设计 |
| 量化数据/研究基础设施 | Python、SQL、数据质量、测试、平台工程 |
| 研究/AI基础设施 | 数学/统计/ML或GPU/分布式，是独立分支 |

### 对路线的影响

- C++、Linux、算法、测试和调试必须前移。
- 数据工程是本科生现实入口，不能只教Pandas API。
- AI不是全部量化开发岗的共同硬门槛。
- RAG/Agent不能替代系统工程和交易链路。
- 国内官方岗位普遍不公开薪资，旧典型薪资结论不能保留。

完整证据见 `resources/招聘市场调研报告.md`。

## 四、主脉络优化

### 旧问题

- 900多行，重复岗位、薪资、公司、资源、进度和阶段说明。
- 同一结论在多个章节重复，更新容易漏。
- 用“5+项目、500题、固定AI比例”代替能力验收。

### 新结构

主脉络只保留:

- 路线选择
- 岗位入口
- 项目层级
- 阶段顺序
- 毕业能力
- 项目梯度
- 闸门

公司岗位和薪资回到招聘报告；资源回到核心清单；实时Day状态回到交接和阶段计划。

## 五、阶段计划优化

### 阶段1

- 保留NumPy/Pandas/Matplotlib、工程化、采集、清洗、回测和项目。
- 移除 `collections/itertools/generator` 集中灌输。
- Day 12改为Git + typing + pytest。
- Day 13只做单一数据源和数据契约。
- Day 14先做本地回测，平台为选做对照。

### 阶段2

- Linux、CMake、GoogleTest和sanitizer前移到Week 1-2。
- 先标准库/RAII，再讲裸指针和手动内存原理。
- 刷题改为独立题 + 间隔重做 + 限时验收。
- 每4周必须有可运行模块。

### 阶段3

- 旧版四周同时做两个项目和多套底层主题，容量失真。
- 新版只做一个 `market-data-replay` 集成项目。
- 内存池、STL源码和高级模板降为选做。

### 阶段4

- 主线至少85%，AI最多15%。
- 先完成行情接收器、SQL/数据质量、微观结构和状态机。
- 再完成回测引擎与交易链路模拟器。
- AI只允许二选一小项目。

### 阶段5-6

- 增加未拿到量化实习时的等价替代路径。
- 最终简历保留2-3个最强项目，不追求项目数量。
- 定向补强一次只选低延迟、数据平台、后端或AI中的一个分支。
