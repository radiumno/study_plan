# 写脉络流程

> 当需要创建新阶段大纲或更新现有大纲时, 按此流程执行.
> 触发条件: 新阶段开始 | 细脉络不存在 | 细脉络与主脉络不匹配

---

## 流程总览

```mermaid
flowchart TD
    A[需要写/更新脉络] --> B[调研: 搜网络优质教程 + 招聘数据 + AI趋势]
    B --> C[验证: 链接有效性 + 资源时效性]
    C --> D[写主脉络: 阶段划分 + 技能-岗位映射 + AI缺口分析]
    D --> E[容量预算: 阶段终点 + 总时间 + 每日上限 + 缓冲]
    E --> F[拆细脉络: 每日知识点 + 练习提纲 + 验收产出]
    F --> G[对齐检查: 7项全过?]
    G -->|否| B
    G -->|是| H[定稿 + commit + push]
```

---

## 步骤详解

### Step 1: 调研

搜索 Python/C++/量化开发/AI大模型 的优质教程 + 招聘数据:

- 主流课程怎么组织知识点顺序
- 每个阶段覆盖哪些内容
- **AI技能在2026年JD中的出现频率** + AI岗位市场数据
- 量化开发岗位的技能需求变化
- **Datawhale AI教程体系**(LLM Cookbook/Happy-LLM/easy-vibe等)的结构

参考源:
- Python: CS50P, Real Python, Python官方 Tutorial
- C++: learncpp.com, cppreference
- AI量化: Qlib(RD-Agent), AlphaCrafter, FinRL-X
- **AI应用**: Datawhale教程体系, LangChain官方文档, HuggingFace课程
- 招聘: BOSS直聘, 猎聘, 牛客网, 知乎, 脉脉高聘

### Step 2: 资源验证 + 持续更新

确认所有链接有效, 资源时效性:

- B站链接是否可访问
- GitHub star 数是否最新
- 教程发布日期是否过时(超过2年需标注)
- 薪资数据来源是否可追溯
- **每进入新阶段前, 重新调研一次对应教程** (不是只调研一次)
- **写每天课程前参考资源库对应章节**, 糅合多家之长

### Step 3: 写主脉络

`resources/主脉络.md` 包括:

1. **阶段划分** — 6阶段从Python到量化系统
2. **技能-岗位映射表** — 每个技能对应哪些岗位要求, 标注匹配度
3. **AI缺口分析** — 哪些AI技能当前未覆盖, 在哪里补充
4. **里程碑** — 每个阶段结束时用户能做什么

### Step 4: 拆细脉络

拆 day 之前必须先做容量预算,依据 `docs/plans/学习量校准规则.md`:

- 阶段终点是什么
- 总共有几周/几天
- 每次学习默认几小时
- 主线/辅线/项目/复习各占多少
- 每天最多引入多少新概念、练习和综合任务
- 至少 10%-20% 时间留给复习、返工、薄弱点

`docs/plans/阶段X_分脉络大纲.md` 按天拆分:

```
## Day X - 标题

### 教学内容
- 知识点列表 (含前置依赖标记, 量化场景)
- 练习规划 (难度递进)
- 练习依赖边界 (每类练习能用哪些已教技术)
- 时间预算 (复习/学/练/综合/复盘)
- 验收产出 (当天结束能检查什么)

### 依赖清单
本 day 用到的所有 Python 类型/语法, 标注来源 day
```

阶段2以后可以先按 week 管理,但进入每个 week 前必须拆成 4-6 个具体学习 day,不能只写“本周学STL/刷题”。

### Step 5: 对齐检查 (7项)

| 检查项 | 标准 | 不通过则 |
|--------|------|----------|
| 1. 主脉络 vs 岗位需求 | 每个知识点对应用人需求? | 增删技能 |
| 2. AI缺口检查 | 当前阶段是否有AI技能覆盖? | 补充AI内容 |
| 2b. **AI辅线覆盖** | 本阶段是否有对应的AI学习内容? | 按量化:AI=60:40分配 |
| 3. 细脉络 vs 主脉络 | 细脉络覆盖了主脉络的阶段内容(含AI)? | 调整细脉络 |
| 4. 细脉络内部依赖 | Day N 用的前置已在 Day < N 教过? | 重排顺序 |
| 5. 练习 vs 知识点 | 每个知识点有对应练习,且练习不依赖未教技术? | 补练习/前移教学/降级题目 |
| 6. 学习量校准 | 每天内容能在容量上限内完成,有缓冲和验收? | 拆天/降级/移到选做 |
| 7. 资源时效性 | 所有链接有效, 数据可追溯? | 更新或标注 |

### Step 6: 定稿

- 更新 `resources/主脉络.md`
- 创建/更新 `docs/plans/阶段X_分脉络大纲.md`
- 如有新的长期教学约束, 优先写入 `AGENTS.md` 或对应 workflow
- 更新 `vault/会话交接.md` 中的最新状态与下次待办
- commit + push (一气呵成)
