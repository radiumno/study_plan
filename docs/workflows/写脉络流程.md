# 写脉络流程

> 触发: 新阶段、阶段目标改变、岗位证据改变、细脉络与主脉络冲突。

## 一、输入

必须先读:

1. `resources/个人信息.md`
2. `resources/招聘市场调研报告.md`
3. `docs/plans/技能需求-权重矩阵.md`
4. `resources/主脉络.md`
5. `resources/核心学习资源清单.md`
6. 当前阶段细脉络
7. `docs/plans/学习量校准规则.md`
8. `docs/plans/规划层级与滚动执行规则.md`
9. `vault/会话交接.md`

## 二、Step 1: 确认触发原因

先写一句:

> 这次改脉络，是因为哪条新证据、哪次Review结果或哪个容量冲突？

没有明确触发原因，不做大改。

## 三、Step 2: 证据复核

### 招聘证据

- 先按岗位族拆分，不把研究岗、交易系统、数据工程和AI基础设施混成一个平均岗位。
- 只用官方岗位页或原始职位页定核心结论。
- 没有逐条样本表时，不写“出现率”“中位薪资”“典型占比”。
- 薪资必须统一币种、周期、经验和岗位层级，否则只作样本。

### 学习资源

- 每阶段最多选1个主教材、1个官方参考、1个项目/练习来源。
- star、播放量和“最新版”不等于优先级。
- 候选资源先进入 `resources/lib/资源库.md`。
- 只有明显优于现有主资源，才进入 `resources/核心学习资源清单.md`。

## 四、Step 3: 更新主脉络

主脉络只负责:

- 路线选择
- 阶段顺序
- 阶段终点
- 项目梯度
- 实习/求职闸门

主脉络不维护:

- 重复的逐日完成状态
- 公司薪资大全
- 全部资源链接
- 未来两年的精确Day表

实时进度只写入交接和当前阶段计划。

## 五、Step 4: 阶段容量预算

先填:

| 项 | 必填 |
|----|------|
| 阶段终点 | 最终可交付什么 |
| 岗位映射 | 对应哪个岗位族和能力 |
| 总时间 | 周数、每周次数、单次时长 |
| 主线比例 | 核心能力/项目/复习 |
| 缓冲 | 至少10%-20% |
| 验收 | 测试、项目、限时题、表达 |
| 删除项 | 容量不够时先删什么 |

不把考研“重叠内容”视为零成本。

## 六、Step 5: 拆阶段和滚动日计划

按 `docs/plans/规划层级与滚动执行规则.md`:

- 当前阶段: 所有剩余Day细化。
- 下一阶段: 周级完整，最近1-2周细化。
- 更远阶段: 只写能力块、项目和闸门。

每个Day必须有:

- 唯一主目标
- 前置依赖
- 新概念上限
- 练习范围
- 时间预算
- 验收产出
- 超量处理

## 七、Step 6: 顺序检查

按以下顺序检查:

1. 正确性基础是否先于性能优化。
2. 工具链和测试是否先于大项目。
3. 单线程正确版本是否先于并发版本。
4. 本地实现是否先于平台封装。
5. 数据质量是否先于策略结论。
6. 回测是否先于实盘。
7. 主线是否先于AI辅线。

## 八、Step 7: 对齐检查

| 检查项 | 通过标准 |
|--------|----------|
| 岗位对齐 | 每个核心能力能映射到岗位族 |
| 主细脉络 | 阶段计划完整覆盖主脉络终点 |
| 依赖 | 后一项依赖已在前面教学/验收 |
| 容量 | 时间与练习可执行 |
| 项目梯度 | 每个项目比前一个新增明确能力 |
| 状态 | 不把课程已写标成Review通过 |
| AI边界 | 主线未过闸时AI不占固定比例 |
| 资源 | 主资源少量、可靠、可访问 |
| 证据口径 | 没有伪统计和无法追溯薪资 |

## 九、Step 8: 同步面

通常更新:

- `resources/主脉络.md`
- 对应阶段计划
- `vault/会话交接.md`

按变化追加:

- 新岗位证据 -> 招聘报告、技能矩阵
- 新核心资源 -> 核心学习资源清单
- 稳定流程规则 -> `AGENTS.md` 或workflow
- 历史重复报告 -> 标记superseded，不继续并行维护

## 十、Step 9: 验证

```bash
python3 scripts/checks.py plans
python3 scripts/checks.py docs
python3 scripts/checks.py tests
python3 scripts/checks.py health
```

完整规划调整通过后再提交本次相关文件。
