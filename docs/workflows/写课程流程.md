# 写课程流程

> 每次用户说"开始今天的学习" / "开始写课" / "继续" 时, 按此流程执行.
> 参考: `resources/主脉络.md` | `docs/plans/阶段X_分脉络大纲.md` | `vault/会话交接.md`

---

## 流程总览

```mermaid
flowchart TD
    A[用户说"开始学习"] --> B[读主脉络 + 会话交接 + 阶段细脉络定位进度]
    B --> C{细脉络存在且吻合?}
    C -->|没有细脉络| D[走 写脉络流程 创建细脉络]
    C -->|对不上主脉络| D
    C -->|是| E[加载记忆规则]
    D --> E
    E --> F[学习量校准: 本day容量和验收是否合理?]
    F --> G[依赖检查: 本day知识点全有前置?]
    G --> H{通过?}
    H -->|漏了前置或超量| I[补前置/拆天/降级]
    I --> F
    H -->|通过| J[写教程 dayXX]
    J --> K[反向检查清单]
    K --> L{全通过?}
    L -->|否| J
    L -->|是| M[更新进度 + 提交]
    M --> N[用户做练习]
    N --> O[用户发代码给AI]
    O --> P[Code Review: 语法/逻辑/风格/量化场景]
    P --> Q{练习全部完成?}
    Q -->|还有没做的| N
    Q -->|全部完成| R[进入下一天]
```

## 步骤详解

### Step 1: 定位进度

读三个文件确定当前位置:

- `resources/主脉络.md` — 当前阶段/当前 day
- `vault/会话交接.md` — 最近会话状态与待办
- `docs/plans/阶段X_分脉络大纲.md` — 当前阶段详细安排
- 如果当前day < Day30(阶段1), 只写量化主线; 如果Day30+(阶段2+), 同时确认AI辅线进度

### Step 2: 核对细脉络

读 `docs/plans/阶段X_分脉络大纲.md`

- **没有这个文件?** → 停, 先走"写脉络流程"创建它
- **对不上主脉络?** → 停, 更新细脉络
- **吻合?** → 以细脉络的当天安排为准

### Step 3: 加载记忆规则

加载 MEMORY.md 中的全部规则, 特别是:

| 规则 | 约束 |
|------|------|
| teaching-explain-every-step | 每参数拆解, 量化场景, Day 05 水平为标准 |
| exercises-must-be-empty | 练习区留空, 反向检查 |
| curriculum-prerequisite-check | 依赖清单 vs 已教清单做 diff |
| daily-progress-display | 开头显示进度 |

### Step 4: 参考多个教程再写

写课前, 翻资源库和研究至少 2-3 个参考源:

1. **看资源库里对应章节** — `resources/lib/资源库.md` 按阶段分类
2. **看官方教程** — Python 官方、NumPy/Pandas 官方、whale-quant
3. **看视频教程** — B站对应主题(尚硅谷/林粒粒/黑马)
4. **⭐ 查 GitHub 资源（根据当前 day）**:

   | 当前Day | 必查资源 | 怎么用 |
   |---------|---------|--------|
   | Day 09-14 (Pandas/Matplotlib) | **yfinance** github.com/ranaroussi/yfinance | 拉真实股票数据做练习，代替假数据 |
   | Day 15-16 (综合项目) | **yfinance** + **资源库量化项目参考** | 用yfinance做数据层，参考freqtrade/backtrader结构 |
   | 阶段1末尾/弹性周 | **start-ai-engineering** github.com/louisfb01/start-ai-engineering | 准备阶段2 AI辅线路线图 |
   | 阶段2+ (AI辅线) | **start-ai-engineering** + **awesome-agentic-ai-zh** | 双路线：英文主线+中文补充练习 |
   | 阶段4+ (量化核心) | **awesome-quant-ai** + **gr8monk3ys/trading-bot** + **Qlib** | 看别人怎么搭AI+量化系统 |
   | 写Claude skill | **agent-skills** github.com/addyosmani/agent-skills | Google Chrome团队的生产级skill参考 |
   | 任何阶段做研究 | **last30days-skill** | 跨平台调研资料，合成摘要 |

对比之后决定:
- 别人怎么组织这个知识点的顺序
- 别人提了什么坑/练习
- 有什么可以糅合到量化场景里的

然后在教程文件顶部标注参考源, 让用户知道来源.

### Step 5: 依赖检查

### Step 5A: 学习量校准

写 day 文件前,先按 `docs/plans/学习量校准规则.md` 核对当天容量:

| 检查项 | 标准 |
|--------|------|
| 阶段目标映射 | 当天内容服务阶段终点,不是临时加戏 |
| 时间预算 | 普通 day 2.5-3h,项目/测试 day 3-4h |
| 新概念数量 | 常规不超过 2-3 个核心新概念 |
| 练习数量 | 按难度设置,超过 10 道需说明或拆分 |
| 验收产出 | 当天结束必须有可检查成果 |
| 超量处理 | 超量就拆天、降为选做或移到后续项目 |

如果用户上一天练习还没稳定完成,当天默认减量: 先复习和补薄弱点,不强推新 day。

### Step 5B: 依赖检查

列出当天用到的所有知识点, 逐个确认前置已教或当天教.

同时按 `docs/plans/练习依赖校准规则.md` 为每道练习做依赖矩阵:

| 项 | 标准 |
|----|------|
| 练习编号 | 每道题都能对应到知识点/块练习/Day综合 |
| 目标能力 | 明确这题练什么,避免题目漂移 |
| 必用技术 | 写清完成题目必须会哪些语法/库/API |
| 已教来源 | 标注 Day X 或本节知识点 X.X |
| 是否越级 | 未教技术不能出现在必做题 |
| 处理方式 | 保留 / 前移教学 / 降级 / 改选做 / 删除 |

依赖边界:
- 复习题只能用过去 day 已教内容。
- 知识点后练习只能用历史已学 + 刚讲知识点。
- 知识块总练习只能用历史已学 + 本知识块已讲内容。
- Day 综合只能用历史已学 + 当天全部已讲内容。
- 选做题可以少量预告未教内容,但不能作为进度门槛。

### Step 6: AI辅线检查 (阶段1后期+)

如果在阶段1末尾(Part 3弹性周附近), 检查主脉络中 AI 辅线的排期:
- 当前进度已到阶段1末尾? → **准备启动 start-ai-engineering**（取代 easy-vibe，详见 `resources/lib/资源库.md` AI辅线升级章节）
- 当前在阶段2+? → 每次写课前检查AI辅线进度标记，量化:AI 保持 60:40
  - 参考资源: **start-ai-engineering**（主线）+ **awesome-agentic-ai-zh**（中文补充练习）

### Step 7: 写教程

结构 (复习+实践 = 左右手):

```
复习环节 (前一天有几个知识块, 就复习几个题)
=== ↓ ===
知识点1.1 (参数拆解/量化场景)
=== ↓ ===
练习1.1.x (按难度和重要程度设置 1-3 道)
=== ↓ ===
知识点1.2 (参数拆解/量化场景)
=== ↓ ===
练习1.2.x (按难度和重要程度设置 1-3 道)
=== ↓ ===
总练习1.x (跨知识块1, 通常 1 道, 复杂块可 2 道)
=== ↓ ===
Day 综合练习 (跨当天知识块)
```

教学标准:
- 每个函数拆解: 函数名(参数1, 参数2) → 参数含义/类型/示例值, 返回类型/含义
- 量化场景: 每个知识点说明"什么时候用, 为什么重要"
- 常见坑: 在踩到之前预先标记

练习提示标准:
- 简单知识点可 1 道题
- 核心或易错知识点可 2-3 道题
- 知识块总练习通常 1 道，复杂块可 2 道
- 只给指向性提示 (1-2句话), 不给分步教程
- 正确: "想想 set 和文件怎么结合" 
- 错误: "用 open() 打开文件, 用 set comprehension 遍历"
- 找bug题不标注行号或类型, 让用户自己发现
- **找bug题格式**: 把 bug 写在代码里, 用户直接在上面改. 不留 `# ↓ 你的代码 ↓`

### Step 8: 反向检查清单 (写完必须过)

| 检查项 | 标准 |
|--------|------|
| 1. 练习区留空 | 每个 `# ↓ 你的代码 ↓` 下面没有可执行代码 |
| 2. 练习不泄漏答案 | 练习描述只写"做什么(what)", 不写"怎么做(how)" |
| 3. 综合练习干净 | 综合练习区没有可执行的 demo 代码。配套函数放 utils |
| 4. 教学细致度达 Day 05 标准 | 每参数拆解, 绑定量化场景 |
| 5. 格式一致性 | 分隔符风格与之前的 day 一致 |
| 6. 提示克制 | 提示不超过 2 句话, 不分步 |
| 7. 复习题数量 | 前一天有几个知识块, 就复习几个题 |
| 8. 练习数量 | 按难度和重要程度动态调整，不机械固定 |
| 9. 学习量合理 | 当天内容符合学习量校准规则,超量内容已拆分或降级 |
| 10. 练习依赖不过界 | 每道必做练习都能只用已教内容完成,未教技术只出现在选做/预告 |

### Step 9: 更新进度

- `resources/主脉络.md` — 状态标记
- `docs/plans/阶段X_分脉络大纲.md` — 标记完成
- `vault/会话交接.md` — 更新当前状态和下次待办

### Step 10: 同步文档站镜像

- 优先运行 `python3 scripts/checks.py docs`
- 再运行 `python3 scripts/checks.py course`
- 新机器或新环境优先先跑 `python3 scripts/checks.py bootstrap`
- 开工前先看状态时，可用 `python3 scripts/checks.py status`
- 想只做快速回归时，可用 `python3 scripts/checks.py tests`
- 推荐最终跑 `python3 scripts/checks.py health`
- 想把检查自动卡在提交前，可先运行 `python3 scripts/checks.py install-hooks`
- 如果校验失败，先修链接/导航/镜像问题，再继续

### Step 11: commit + push

- `git add -A && git commit -m "dayXX: 描述"`
- 注意: 如果无远程仓库(origin), 跳过 push, 只 commit

### Step 12: Code Review (用户做完练习发代码时)

用户在练习区写完代码后发给我, 按此流程 review:

1. **跑一遍**: 用户代码是否能正常运行? 结果对不对?
2. **逐函数看逻辑**: 有没有边界情况没处理? (空列表、None、类型不匹配)
3. **找 bug**: 索引越界? 可变/不可变混用? 类型错误?
4. **提优化**: 能不能更 Pythonic? (推导式代替循环、解包代替索引)
5. **量化场景**: 代码在实际量化场景中的表现 (大数据量会慢吗?)
6. **记录薄弱点**: 用户卡住的知识点, 记入 `vault/20_WIKI/` 作为后续复习素材

如果用户还有遗留练习没做, 先标记未完成, 等全部完成后再进下一天.
