# 写课程流程

> 每次用户说"开始今天的学习" / "开始写课" / "继续" 时, 按此流程执行.
> 参考: `主脉络.md` | `阶段X_分脉络大纲.md` | `memory/`

---

## 步骤详解

### Step 1: 定位进度

读两个文件确定当前位置:

- `resources/主脉络.md` — 当前阶段/当前 day
- `.claude/CLAUDE.md` 的 `## 当前状态` 节
- 如果当前day < Day30(阶段1), 只写量化主线; 如果Day30+(阶段2+), 同时确认AI辅线进度

### Step 2: 核对细脉络

读 `docs/plans/阶段X_分脉络大纲.md`

- **没有这个文件?** → 停, 先走"写脉络流程"创建它
- **对不上主脉络?** → 停, 更新细脉络
- **吻合?** → 以细脉络的当天安排为准

### Step 3: 加载记忆规则

加载 MEMORY.md 中的全部规则, 特别是:

| 规则 | 约束 |
|------|------|
| teaching-explain-every-step | 每参数拆解, 量化场景, Day 05 水平为标准 |
| exercises-must-be-empty | 练习区留空, 反向检查 |
| curriculum-prerequisite-check | 依赖清单 vs 已教清单做 diff |
| daily-progress-display | 开头显示进度 |

### Step 4: 依赖检查

列出当天用到的所有知识点, 逐个确认前置已教或当天教.

### Step 4.5: 参考多个教程再写 (新增)

写课前, 翻资源库和研究至少 2-3 个参考源:

1. **看资源库里对应章节** — `resources/lib/资源库.md` 按阶段分类
2. **看官方教程** — Python 官方、NumPy/Pandas 官方、whale-quant
3. **看视频教程** — B站对应主题(尚硅谷/林粒粒/黑马)

对比之后决定:
- 别人怎么组织这个知识点的顺序
- 别人提了什么坑/练习
- 有什么可以糅合到量化场景里的

然后在教程文件顶部标注参考源, 让用户知道来源.

### Step 5: 写教程

结构 (复习+实践 = 左右手):

```
前情回顾 (复习上day核心, 1-2道小题)
=== ↓ ===
抽题回练 (从3-7天前的练习中抽1道, 对抗遗忘曲线)  ← 新增
=== ↓ ===
新知识点教学 (参数拆解/量化场景)
=== ↓ ===
新知练习 (紧跟知识点, 指向性提示)
=== ↓ ===
综合练习 (跨当天知识点)
=== ↓ ===
预告明天
```

教学标准:
- 每个函数拆解: 函数名(参数1, 参数2) → 参数含义/类型/示例值, 返回类型/含义
- 量化场景: 每个知识点说明"什么时候用, 为什么重要"
- 常见坑: 在踩到之前预先标记

练习提示标准:
- 只给指向性提示 (1-2句话), 不给分步教程
- 正确: "想想 set 和文件怎么结合" 
- 错误: "用 open() 打开文件, 用 set comprehension 遍历"
- 找bug题不标注行号或类型, 让用户自己发现
- **找bug题格式**: 把 bug 写在代码里, 用户直接在上面改. 不留 `# ↓ 你的代码 ↓`

### Step 6: 反向检查清单 (写完必须过)

| 检查项 | 标准 |
|--------|------|
| 1. 练习区留空 | 每个 `# ↓ 你的代码 ↓` 下面没有可执行代码 |
| 2. 练习不泄漏答案 | 练习描述只写"做什么(what)", 不写"怎么做(how)" |
| 3. 综合练习干净 | 综合练习区没有可执行的 demo 代码。配套函数放 utils |
| 4. 教学细致度达 Day 05 标准 | 每参数拆解, 绑定量化场景 |
| 5. 格式一致性 | 分隔符风格与之前的 day 一致 |
| 6. 提示克制 | 提示不超过 2 句话, 不分步 |

### Step 7: 更新进度

- `resources/主脉络.md` — 状态标记
- `docs/plans/阶段X_分脉络大纲.md` — 标记完成
- `.claude/CLAUDE.md` — 更新当前状态

### Step 8: commit + push

- `git add -A && git commit -m "dayXX: 描述" && git push`
- 不再问"要不要 commit", 直接提交推送一气呵成

### Step 9: Code Review (用户做完练习发代码时)

用户在练习区写完代码后发给我, 按此流程 review:

1. **跑一遍**: 用户代码是否能正常运行? 结果对不对?
2. **逐函数看逻辑**: 有没有边界情况没处理? (空列表、None、类型不匹配)
3. **找 bug**: 索引越界? 可变/不可变混用? 类型错误?
4. **提优化**: 能不能更 Pythonic? (推导式代替循环、解包代替索引)
5. **量化场景**: 代码在实际量化场景中的表现 (大数据量会慢吗?)
6. **记录薄弱点**: 用户卡住的知识点, 记入 memory/ 作为后续复习素材

如果用户还有遗留练习没做, 先标记未完成, 等全部完成后再进下一天.
