# 每周优化审查流程

> 目的: 检查学习是否真的推进、规划是否仍可执行、事实来源是否漂移。
>
> 周审不是每周重写路线，也不是机械搜新资源。

## 一、触发

- 每完成3-5个学习Day
- 一个Block结束
- 用户连续卡住或课程返工增多
- 外部岗位证据发生明显变化
- 健康检查发现规划口径冲突

## 二、Phase 1: 快速基线

```bash
python3 scripts/checks.py status
python3 scripts/checks.py plans
python3 scripts/checks.py course
```

检查:

- 用户实际状态、交接、阶段计划是否一致。
- 是否把“课程已写”误标为“Review通过”。
- 当前Day是否有未完成或未Review练习。
- 工作树是否包含用户答案和无关改动。

## 三、Phase 2: 学习结果审计

### 2.1 当前能力

- 最近Day的验收是否通过。
- 用户能否脱离示例完成迁移任务。
- 薄弱点是否在后续复习中出现。
- 是否出现“看懂了但写不出”的信号。

### 2.2 课程质量

- 教学是否解释清楚。
- 示例是否过大。
- 练习是否复制教学代码。
- 总练习是否只是子题拼接。
- 单日容量是否真实。

### 2.3 依赖

- 新练习是否使用未教内容。
- 项目是否提前引入框架、数据库、并发或AI。
- 前置不稳时是否仍机械推进。

## 四、Phase 3: 规划审计

对照:

- `resources/主脉络.md`
- 当前阶段计划
- `docs/plans/规划层级与滚动执行规则.md`

检查:

1. 当前阶段终点是否仍合理。
2. 下一批1-2周Day是否已细化。
3. 更远阶段是否过度精确。
4. 项目是否重复或过多。
5. AI是否绕过主线闸门。
6. 考研、校内课和项目时间是否被重复计算。

## 五、Phase 4: 证据与资源审计

### 招聘

只有以下情况才联网复核:

- 距上次复核超过3个月。
- 当前要进入新阶段。
- 用户准备投递。
- 新岗位证据可能改变路线。

复核必须保存岗位样本，不能只更新口头百分比。

### 资源

- 当前核心资源是否够用。
- 是否有失效链接或版本问题。
- 候选资源是否明显优于核心资源。
- 是否因为star/播放量不断堆资源。

新资源默认进入候选库，不直接进课程。

## 六、Phase 5: 项目治理审计

```bash
python3 scripts/checks.py docs
python3 scripts/checks.py tests
```

检查:

- 主事实来源是否重复。
- 旧报告是否仍与当前规则冲突。
- README、docs首页、导航是否写死旧进度。
- 生成镜像是否只由源文件同步。
- 检查脚本是否覆盖本周新发现的稳定问题。

## 七、优先级

| 级别 | 定义 | 处理 |
|------|------|------|
| P0 | 会导致错误学习、状态误判或路线偏移 | 本次立即修 |
| P1 | 明显降低质量或造成返工 | 本周修 |
| P2 | 可维护性和表达优化 | 有余量再修 |

## 八、报告模板

写入 `docs/reviews/audit-YYYY-MM-DD.md`:

```markdown
# 审查报告

## 结论

## P0/P1问题

## 学习结果

## 规划与依赖

## 证据与资源

## 已修复

## 暂不处理

## 下一周期闸门
```

## 九、流程迭代

只有当本周发现的是“可重复出现、可提前拦截”的问题，才更新:

- `AGENTS.md`
- workflow
- 检查脚本

一次性内容错误只修内容，不无限增加规则。

## 十、收口

```bash
python3 scripts/checks.py health
```

完整通过后再提交本次审查相关文件。
