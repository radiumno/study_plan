# 教学与练习设计参考

## 一、参考资源带来的启发

| 资源 | 可复用设计 | 不直接照搬 |
|------|------------|------------|
| CS50P | 少量完整问题、明确输入输出、自动验证 | 每周节奏和通用题材 |
| Exercism | 函数边界、测试驱动、单一概念练习 | 直接提供过多stub |
| Python官方教程 | 权威语义和最小示例 | 缺少独立练习 |
| NumPy/Pandas/Matplotlib官方文档 | 参数、返回、边界和当前API | 文档顺序不等于教学顺序 |
| MIT Missing Semester | 工具、调试、版本控制和代码质量 | 一周密集课程节奏 |

## 二、教学单元

每个新概念按以下顺序:

1. 问题: 为什么需要它。
2. 模型: 核心对象或机制。
3. API: 常用参数、返回和副作用。
4. 示例: 一个知识点一个最小示例。
5. 边界: 常见错误和限制。
6. 场景: 在量化数据或系统中何时使用。
7. 迁移练习: 换目标、数据或约束。

## 三、练习层级

| 层级 | 目的 | 形式 |
|------|------|------|
| 回忆 | 确认前置仍在 | 简答、读代码、预测输出 |
| 单点 | 使用刚学知识 | 小函数、参数对比 |
| 迁移 | 防止复制示例 | 换数据、目标或边界 |
| 诊断 | 暴露误解 | 找bug、解释异常结果 |
| 综合 | 组织完整过程 | 新场景、数据关系和判断任务 |

## 四、练习数量

练习数由时间和难度决定，不设“每天10-15题”常量。

| 知识点 | 建议 |
|--------|------|
| 简单且低风险 | 1道迁移题 |
| 核心API | 1-2道迁移/诊断题 |
| 易错机制 | 2-3道不同角度题 |
| 知识块 | 1道完整场景综合 |
| Day | 1道跨块综合或项目产出 |

超过10道且仍有大综合时，默认超量。

## 五、题面规则

### 必做题

- 只写做什么、输入输出和验收。
- 不列具体步骤。
- 不在提示中补完整做法。
- 只依赖已教内容。

### 提示

提示只允许:

- 指向一个概念
- 提醒一个边界
- 给一个检查问题

提示不允许:

- 分步骤列算法
- 写出关键API组合
- 给出接近答案的伪代码

### 选做题

- 可以预告少量未教内容。
- 必须明确不影响进度。
- 不作为下一Day前置。

## 六、综合题标准

知识块总练习必须至少引入一种新东西:

- 新业务目标
- 新数据关系
- 新约束
- 新异常
- 新判断任务

不合格:

> 把练习1、练习2、练习3再做一遍。

合格:

> 给一份新的行情数据，选择合适工具完成清洗、指标和解释，并说明一个结果为什么值得怀疑。

## 七、验证设计

每道练习至少有一种验证:

- 明确预期输出
- 自动测试
- 图表验收
- 数据契约
- 性能基线
- 文字解释标准

项目型任务需要同时验证正确性和可复现性。

## 八、课程长度判断

不要用文件行数判断课程是否足够。

看以下指标:

- 是否覆盖唯一主目标
- 新概念是否解释清楚
- 是否有迁移和综合
- 用户是否能在预算内完成
- 是否留下可检查产出

课程短但完整可以通过；课程长但堆示例和重复练习仍不合格。

## 九、Review反馈回流

用户出现以下信号时调整:

| 信号 | 处理 |
|------|------|
| 直接复制示例 | 增加迁移，不加更多讲解代码 |
| 会写但解释不清 | 增加解释/诊断题 |
| 语法频繁卡住 | 减少新概念，补单点练习 |
| 综合题完全无从下手 | 拆前置能力，不泄漏综合答案 |
| 练习耗时远超预算 | 下一个Day减量或安排返工 |
