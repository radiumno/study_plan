# 量化开发招聘市场调研报告

> 采集日期: 2026-07-10
>
> 本版替代此前按搜索结果估算“岗位出现率”“典型薪资”和岗位占比的口径。没有逐条编码的岗位样本，不再写成市场统计。

## 一、调研范围与证据规则

### 1.1 本轮回答的问题

1. 量化开发到底包含哪些不同岗位族。
2. 本科生可投的真实入口有哪些。
3. 哪些能力是跨岗位稳定出现的核心要求。
4. 哪些能力只属于低延迟、量化研究或 AI 基础设施分支。
5. 当前学习路线应该保留、前移或降级什么。

### 1.2 来源等级

| 等级 | 含义 | 本轮用途 |
|------|------|----------|
| A | 公司官方招聘页、官方校招页、官方岗位页 | 作为核心证据 |
| B | 招聘平台原始职位页、学校就业网转发的公司招聘信息 | 补充岗位细节 |
| C | 社区、媒体、聚合页 | 只作线索，不用于定结论 |

### 1.3 重要限制

- 国内公司官方页通常不公开薪资，因此本报告不提供“行业中位数”。
- 个别高薪实习样本只能说明上限存在，不能当作典型水平。
- 招聘页会持续变动，岗位是否开放应在投递前重新核验。
- 本报告聚焦工程岗位，不把量化研究员要求混入量化开发主线。

## 二、岗位族拆分

### 2.1 交易系统 / 低延迟工程

**典型工作:**

- 行情接入、交易所协议、订单路由、订单状态机
- 高吞吐交易系统、低延迟网络、进程间通信
- 实盘监控、故障恢复、性能分析与优化

**稳定核心能力:**

- C++、Linux、数据结构与算法
- 并发、多线程、网络编程
- 操作系统、计算机体系结构、内存与缓存
- 性能测量、测试、监控和工程交付

**分支能力:**

- FPGA、Verilog、PCIe/DMA、RDMA、内核或协议栈

这类岗位最接近当前项目的主目标，也是门槛最高的工程分支。

### 2.2 策略系统 / 研究平台工程

**典型工作:**

- 仿真回测、组合优化、研究平台和批处理工具
- 海量时序金融数据处理
- 研究代码工程化、生产部署、分布式计算

**稳定核心能力:**

- C++ 与 Python
- Linux、算法与数据结构
- 并发/并行、数值计算、系统设计
- 回测、数据质量、可复现研究流程

这类岗位兼顾系统工程和量化业务，比纯低延迟岗位更适合用“Python 数据能力 + C++ 系统能力”切入。

### 2.3 量化数据 / 研究基础设施工程

**典型工作:**

- 数据采集、清洗、质量监控、血缘和可追溯性
- Python/SQL 数据管道、研究工具、报表和内部 API
- 支持因子研究、组合构建和交易成本分析

**稳定核心能力:**

- Python、SQL、Linux、Git
- 数据建模、数据质量、测试和可维护性
- 大规模数据处理；部分岗位需要 C++、分布式系统

这是本科生较现实的第二入口，但不能停留在“会 Pandas”，还需要工程质量和数据可靠性。

### 2.4 量化研究 / 机器学习研究

**典型工作:**

- Alpha 研究、统计建模、组合优化、机器学习
- 大规模数据实验、模型评估和研究表达

**稳定核心能力:**

- 数学、统计、研究能力
- Python/R/MATLAB、机器学习框架
- 研究项目、论文或竞赛经历

这不是当前量化开发主线。部分官方岗位允许优秀本科生，但硕士/博士偏好更明显，不能把它的要求平均到工程路线中。

### 2.5 AI / 高性能计算基础设施

**典型工作:**

- GPU/CPU 高性能计算、分布式训练、推理优化
- MLOps、计算集群、存储与网络优化

**稳定核心能力:**

- C++、Python、Linux、分布式系统
- GPU 架构、CUDA/RDMA、模型系统

这是独立高门槛分支。RAG/Agent 应用开发不能替代这里要求的系统能力。

## 四、本科生可行性

### 4.1 可以确认的事实

- 宽德策略系统和交易系统校招页面均写明“重点本科及以上”。
- 启林官方校园招聘列表存在面向应届本科的量化开发岗位。
- IMC、Citadel、Two Sigma、Jane Street 等官方学生岗位接受本科生或本科在读生。
- 多个官方工程岗位明确写“不要求金融背景”，但要求很强的编程、算法和工程能力。

### 4.2 必须正视的现实

- “本科可投”不等于“普通准备即可通过”。
- 国内头部公司普遍存在学校、竞赛、实习和项目质量偏好。
- 对当前学习者而言，最可靠的路线不是只押头部低延迟岗，而是同时覆盖:
  1. 量化交易/策略系统
  2. 金融数据与研究平台
  3. C++ 系统或 FinTech 后端

### 4.3 本科路线的证明材料

比“学过什么”更有说服力的是:

- 2-3 个可运行、可测试、可解释的核心项目
- CMake/测试/CI/基准测试/故障复盘
- 算法题的稳定解题能力和错题复盘
- 一段实习、实验室、开源贡献或真实协作经历
- 能讲清一次从需求、设计、实现、验证到改进的完整过程

## 五、薪资与岗位数量口径修正

### 5.1 本版取消的旧结论

以下写法不再保留:

- “C++ 实习普遍达到数千元日薪”
- “Python 与 C++ 实习薪资相差 5-10 倍”
- “某技能在 40%/60%/90% 以上岗位出现”
- “量化开发典型薪资为某个固定区间”

原因是旧报告没有保存逐条岗位编码表，搜索摘要也可能把月薪、年薪、项目奖金或异常职位误读为同一口径。

### 5.2 可以保留的判断

- 顶级量化机构确实存在极高薪实习和正式岗，但属于高选择性样本。
- 交易系统/低延迟 C++ 的稀缺性和技术上限通常高于普通 Python 数据岗位。
- 是否值得投入不能只看薪资上限，还要看可进入性、岗位数量、技能可迁移性和个人证据。

## 六、对学习路线的直接修正

| 优先级 | 修正 | 依据 |
|--------|------|------|
| P0 | C++、算法、Linux、测试和调试前移 | 所有工程岗位族的共同底座 |
| P0 | 项目从“功能演示”升级为“可运行、可测试、可测量” | 官方岗位强调生产质量和工程交付 |
| P0 | 阶段4继续保留回测与交易链路双项目 | 直接对应研究平台和交易系统岗位 |
| P1 | Python阶段保留数据清洗、质量验证和回测基础，但删除低价值工具堆叠 | Python是必要入口，不是主要差异化壁垒 |
| P1 | SQL和数据质量落到真实项目 | 数据/研究平台是本科可投入口 |
| P1 | AI改为门槛触发的辅线，不固定占25%-40% | AI要求集中在独立岗位族，不能平均到全部量化开发 |
| P2 | FPGA/CUDA/RDMA在阶段6按目标岗位选择 | 高价值但前置要求高，过早学习会挤压主线 |

## 八、下轮复核

建议每季度只做一次有边界的复核:

1. 选 20-30 个仍开放的官方岗位。
2. 保存岗位标题、岗位族、学历、技能、地点和日期。
3. 逐条编码后再计算频次。
4. 薪资只保留同币种、同周期、同经验层级的可比样本。
5. 只有结论发生变化时，才调整主脉络。

### 还没覆盖的方向

- 中国香港、新加坡的本科实习和签证限制。
- 国内券商 IT、交易所技术、金融数据供应商岗位。
- 当前学校校友在量化、券商科技和 FinTech 的真实去向。
- 2027 届国内暑期实习的开放时间和批次节奏。
