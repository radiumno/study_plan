# Search Mastery — 搜索能力最大化框架

调用条件：当用户需要查数据、做研究、对比选项时，**必须先加载本skill**再开始搜索。

---

## 1. 启动搜索前的必问问题

在开始任何搜索之前，先问自己（和用户）这些问题。**不回答完不动手。**

### 1.1 用户背景确认
- 用户是什么专业背景？（计算机/统计/金融/其他 → 影响考试科目难度评估）
- 用户的核心约束是什么？（经济条件？地理位置？名校情结？）
- 用户有哪些显性的偏好？（城市、学校层次、专业方向）

### 1.2 搜索范围确认
- 这个问题有哪些可能的答案方向？列出至少3个再开始搜
- 我有没有默认的限制？（比如只搜了某个城市、只搜了某种专业）
- **主动问自己：你现在的框架是什么？写出来，然后反驳它。**

## 2. 工具选择决策树

```
需要什么类型的数据？
│
├─ 一个具体数字（分数线/学费/报录比）
│   → WebSearch（最快）
│   → 如果官网打不开或数据在图片里 → cloak-fetch
│
├─ 多个选项的多维度对比（3~5个选项）
│   → 先WebSearch分别搜每个选项
│   → 然后自己拉表对比
│
├─ 系统性研究（5个以上角度、需要交叉验证）
│   → 调 Workflow({name: "deep-research", args: "..."})
│   → 注意：确认工具调用真正执行了，不是只调了Skill没调Workflow
│
├─ 官网被墙 / 需要JS渲染 / 图片里的数据
│   → 调 Skill("cloak-fetch", url)
│   → 注意：中文站不加--proxy，海外站加--proxy
│
└─ 数据缺口找不到替代来源
    → 诚实地列出缺口，不要编造
    → 告诉用户"这个数据可以通过XX渠道查到"
```

## 3. 数据可信度等级标注

每个关键数据必须标注来源等级。**不标注等于没来源。**

| 等级 | 标签 | 含义 | 示例 |
|------|------|------|------|
| 🔵 一手官方 | 学校官网、政府数据、原始PDF | 可以直接引用 | "华科官网复试细则写的" |
| 🟢 二手权威 | 新闻转载的官方数据、可信媒体报道 | 可以引用但注明转载 | "每日经济新闻引用的行业数据" |
| 🟡 辅导机构 | 考研机构整理的数据 | 仅作参考，可能不准 | "新东方考研整理的数据" |
| 🔴 论坛/推测 | 知乎、贴吧、个人估算 | **不要用** | — |

**呈现格式：**
> 华科计算机专硕315分（🔵 华科计算机学院官网2025复试细则）

## 4. 自我纠偏检查清单

搜索过程中或呈现结果前，逐条检查：

- [ ] 我有没有只搜了1~2个城市？其他城市考虑了吗？
- [ ] 我有没有只搜了1种专业方向？其他方向考虑了吗？
- [ ] 我有没有假设用户背景A但其实是B？
- [ ] 我标了来源等级吗？
- [ ] deep-research workflow真正启动了吗？还是只调了Skill没调Workflow？
- [ ] 有数据缺口时，我尝试了cloak-fetch吗？还是直接说"搜不到"？
- [ ] 薪资/收入数据：是JD上的真实数字，还是新闻稿里的行业估算？

**核心自省问题：**
> "还有哪些选项我没考虑到？列出3个然后解释为什么之前没提。"

**做完检查之后再输出结果，不要边搜边出结果。**

## 5. 搜索流程模板

```
--- 搜索任务: [主题] ---
用户背景: [专业/约束/偏好]
搜索范围: [城市/专业方向/其他限制]

[Step 1] 基础数据收集（WebSearch）
  - 关键词1 → 结果
  - 关键词2 → 结果

[Step 2] 数据补缺（cloak-fetch）
  - 打不开的官网 → cloak-fetch抓取
  - 图片里的数据 → cloak-fetch提取

[Step 3] 交叉验证
  - 数据A：来源1 → 来源2 → 是否一致？
  - 数据B：来源1 → 来源2 → 是否一致？

[Step 4] 整理输出
  - 对比表（标注可信度等级）
  - 局限性说明（没找到的数据、不确定的数据）
```

## 6. 历史教训备忘录

| # | 错误场景 | 错误原因 | 正确操作 |
|---|---------|---------|---------|
| 1 | 只搜了武汉和上海的学校 | 被用户的地理位置和偏好预设限制了 | 第一步就搜全国范围 |
| 2 | 默认用户是统计/数学背景 | 没确认专业就假设了 | 先问"你什么专业" |
| 3 | 数据缺口说"搜不到"就放弃 | 没尝试cloak-fetch | 官网数据用cloak-fetch抓取 |
| 4 | 薪资数据来源等级混用 | 没区分JD薪资和新闻估算 | 每个数字标注可信度等级 |
| 5 | 调了deep-research Skill但没调Workflow | 以为Skill调用等于执行了 | 确认Workflow工具被实际调用 |
| 6 | 研究ROI时的年薪增长曲线 | 合理推断但没说明是推断 | 标注"这是基于XX数据的推断" |

## 7. Claude Code搜索设计哲学（来自逆向分析）

Claude Code 的搜索架构：**Grep Over RAG**

- 代码搜索：用 grep/glob 而非向量索引 — 实时、零配置、确定性强
- Web搜索：WebSearch（找链接）→ WebFetch（提取内容）→ 主模型综合
- WebFetch 用 Haiku 3.5 做预过滤，只返回摘要，不返回原始HTML
- 设计原则：**无状态 + Just-in-Time Context** — 只在需要时加载上下文

**对我做研究的启示：**
- WebSearch只是搜到链接，真正的内容要用WebFetch去拉
- 一次WebFetch加prompt指定"提取XX数据"，比多次无方向搜索高效
- 搜索查询要**自包含**（搜索引擎没有对话上下文）

## 8. 高级搜索策略

### 8.1 约束驱动搜索（strategic-search skill）
1. 提取所有约束条件
2. 按独特性和可搜索性排序
3. 从最独特的约束开始搜
4. 逐条验证 → 碰到硬约束失败立即淘汰
5. 满足所有条件立刻停止

### 8.2 搜索查询优化四原则
| 原始写法 | 优化策略 | 优化后 |
|---------|---------|-------|
| 模糊描述 | 具体化 | 用精确术语 |
| 问句形式 | 提取关键词 | 名词组合 |
| 口语化 | 使用专业术语 | 行业黑话 |
| 太宽泛 | 添加上下文限定 | 加限定词 |

### 8.3 多源交叉验证
- 同一个数据查3个不同来源
- 不一致时：以一手官方 > 二手权威 > 辅导机构 为准
- 无法验证的数据明确标注"未验证"

### 8.4 多AI合成策略（打破信息茧房）
- 同一问题用不同搜索词/不同角度搜索
- 从相互矛盾的信息中识别真相
- 如果搜索结果高度一致 → 结论可靠
- 如果结果矛盾 → 标注为"存在争议"

## 7. 用户常说的纠偏语句（提前预判）

当用户说这些话时，意味着我该怎么做：

| 用户说 | 我该意识到 |
|-------|----------|
| "你是不是被限制了" | 搜索范围太窄，立即列出其他可能性 |
| "这是猜的还是搜的" | 数据可信度标注不够清晰 |
| "还有呢" | 我给的选项不够全面 |
| "学校的官网数据呢" | 我偷懒了，应该用cloak-fetch去拿 |
| "你就搜了这些？" | 搜索深度不够，应该多角度重复搜索 |
