# Claude Code 犯错记录

## 1. Day 02 漏教元组 (tuple)

**错误:** Day 02 只讲了 list 和 dict，没讲 tuple。Day 03 用 `*args`（返回元组）时用户问"*是数组吗"，才发现缺失。

**原因:** 拿到 Day 02 计划时没有做依赖检查——四大基础类型 (list/dict/tuple/set) 应该全部在阶段 1 早期覆盖，但执行前没核对。

**教训:** 写每 day 教程前必须列依赖清单，确认本 day 用到的基础类型在之前都已教过。已写入 [[curriculum-prerequisite-check]]。

---

## 2. 答疑不遵守教学模式

**错误:** 用户问元组是什么、`**kwargs` 是什么时，直接用表格/简短文字回答，没有按项目要求的格式（知识点→C++对比→量化场景→练习）。

**原因:** 脑子里把"答疑"和"教学"当成了两件事，觉得小问题快速回答就行。但项目指令没有给答疑开例外。

**教训:** 所有涉及新知识点的回答，不管问题大小，一律遵守 CLAUDE.md 的教学模式。已写入 [[curriculum-prerequisite-check]]。

---

## 3. 内置函数 (`len/sum/max/min/sorted`) 从未正式教学

**错误:** `len()` 在 Day 02 练习里直接用了；`sum()` 完全没讲；`max()/min()` 在 Day 03 练习 5 的 lambda 部分才出现，但练习 3 已经让学生手写找最大最小值。

**后果:** 学生手写了 `find_max`、`find_min` 函数，不知道 Python 有内置的 `max()`、`min()`，浪费了时间，也错过了"Python 比 C++ 简洁"的学习机会。

**原因:** 这些函数太基础，我默认"看一遍就会了"，没有按教学规范处理。这是"知识的诅咒"——会了之后很难想象别人不会。

**教训:** 不能假设任何知识点"太简单不用讲"。内置函数应该在它们首次被需要的那个 day 统一教学。具体哪些要在 Day 02 补，见 [[curriculum-prerequisite-check]]。

---

## 4. Day 03 练习题之间没有分隔符

**错误:** Day 03 写完教程后，6 个练习区块之间没有像 Day 02 那样的 `print("\n" + "=" * 40 + "\n练习 N")` 分隔。

**原因:** 写教程时关注点在教学内容和练习题目本身，忽略了格式一致性。用户自己发现后让我补上。

**教训:** 每写完一个 day 的教程，对照前一个 day 检查格式：分隔符、缩进风格、注释风格是否一致。

---

## 5. Day 02 验证了已教代码但没验证"没教什么"

**错误:** 写 Day 02 时知道当天教了 list/dict/comprehension，但没反向检查"还有什么基础类型没教"。结果 tuple 被遗漏，到 Day 03 才暴露。

**原因:** 只做了正向验证（教了什么），没做反向验证（漏了什么）。

**教训:** 每完成一个 day，更新一张"已教清单"，和"应该教清单"做 diff。应该在 Day 02 结束时就能发现 tuple 和 set 还没覆盖。

---

## 总结模式

| 错误类型 | 出现次数 | 根因 |
|---------|---------|------|
| 漏教前置知识 | 2 次 (tuple, 内置函数) | 不检查依赖清单 |
| 格式不遵守 | 2 次 (答疑, 分隔符) | 脑补例外, 不参照前例 |
| 知识诅咒 | 1 次 (内置函数) | 默认"太简单不用讲" |

**核心改进: 每次行动前先检查——依赖清单、教学模式、格式一致性。三个全过再动手。**
